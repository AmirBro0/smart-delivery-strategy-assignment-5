# Памятка для защиты Assignment 5

Проект выбирает подходящий маршрут из восьми заранее заданных вариантов. Сначала
он проверяет ограничения, затем применяет выбранную стратегию. Все пять стратегий
используют один интерфейс RouteStrategy.

## Что показать преподавателю

1. Запустить `java -jar dist/smart-delivery.jar --compare`: один запрос обрабатывают
   пять алгоритмов. Fastest выбирает R02, Cheapest и Eco выбирают R05,
   Balanced выбирает R06, Distance First выбирает R07.
2. Открыть RoutePlanner.java: в нём есть только ссылка на интерфейс, смена
   стратегии и делегирование. Вычисления оценок находятся в отдельных классах.
3. Запустить `--switch`: один объект RoutePlanner трижды меняет алгоритм.
   Дополнительно тот же Fastest выбирает R03 вместо R02 после уменьшения бюджета.
4. Запустить `--auto`: StrategySelector выбирает алгоритм по приоритету и ecoPreferred.
   Срочность важнее экологического предпочтения. Остальные соответствия задаёт Map.
5. Запустить `--failures`: пустой список, отсутствие допустимого маршрута,
   неправильные веса, отрицательный бюджет обрабатываются явно.
6. Выполнить `powershell -ExecutionPolicy Bypass -File .\build.ps1` либо `mvn test`:
   должно пройти 51 тест. Показать обе UML-диаграммы в отчёте.
7. Открыть `git show 9baf7b3`: пятая стратегия добавлена отдельным коммитом.
   Из существующих производственных классов изменился только DemoData для регистрации.

## Короткие ответы

**Где Context?** RoutePlanner. Он не знает, как именно сравнивают маршруты.

**Где Strategy?** Интерфейс RouteStrategy. Concrete Strategies — пять классов
FastestRouteStrategy, CheapestRouteStrategy, EcoFriendlyRouteStrategy,
BalancedRouteStrategy и DistanceFirstStrategy.

**Зачем RouteDecision вместо Route?** Требуется объяснить выбор. RouteDecision
возвращает маршрут, оценку, метрики, формулу и оценки всех кандидатов вместе.

**Чем Selector отличается от Strategy?** Selector выбирает способ решения,
Strategy выбирает маршрут этим способом. Условия политики не содержат формул
оптимизации. Соответствия приоритетов и алгоритмов находятся в переданной Map.

**Почему Fastest не просто min по времени?** Используется базовое время плюс
задержки из-за трафика и погоды. Эти же итоговые минуты проверяются по дедлайну.

**Как считается цена?** Базовая цена + километры * тариф + надбавка за приоритет
+ дополнительные сборы. Надбавки: URGENT 500, STANDARD 150, ECONOMY/ECO 0 KZT.
Это учебные значения. Сумма вычисляется через BigDecimal, затем округляется один
раз до двух знаков HALF_UP. Бюджет проверяется по полной цене.

**Зачем нормализация Balanced?** Время, деньги, расстояние и выбросы имеют разные
единицы и масштабы. Для каждого показателя используется (x-min)/(max-min) только
среди допустимых маршрутов. Если все значения одинаковые, нормализованное значение
равно нулю. Веса 0.4, 0.3, 0.1, 0.2 в сумме равны единице; неверные веса отклоняются.

**Что происходит при равенстве оценок?** Выбирается маршрут с меньшим строковым ID.
Поэтому результат не зависит от порядка входного списка.

**Может ли запрещённый маршрут выиграть?** Нет. ConstraintChecker сначала
фиксирует все нарушения. AbstractRouteStrategy оценивает только допустимые варианты.
Недоступный R08 не выигрывает, хотя его исходные показатели очень хорошие.

**Что если подходящих маршрутов нет?** NoSuitableRouteException с объяснением и
списком проверок кандидатов. Возврата null нет. Режим сравнения сохраняет отдельную
ошибку для каждой стратегии.

**Какие SOLID видны?** SRP: планировщик, проверки, политика и алгоритмы разделены.
OCP: новая стратегия добавляется классом и регистрацией. DIP: RoutePlanner зависит
от RouteStrategy, а не от конкретных алгоритмов.

**Strategy и Bridge?** Strategy заменяет алгоритм одной операции. Bridge разделяет
две независимо изменяемые иерархии — абстракции и реализации. Содержимое предыдущего
задания в этот проект не включено; сравнение относится к самим паттернам.

**Ограничения проекта?** Он выбирает готовый маршрут для одного заказа, не строит
дорожный граф и не распределяет автопарк. Трафик задан заранее. Balanced сейчас
O(n^2), потому что пересчитывает диапазоны: улучшение — вычислить их один раз
на запрос. RoutePlanner со сменяемой стратегией используется одним потоком.

## Примеры изменения на защите

- Заменить веса на `new BalancedRouteStrategy(1, 0, 0, 0)`: выбор станет R02.
- Снизить бюджет стандартного запроса до 2500: Fastest выберет R03.
- Установить лимит CO2 меньше выбросов выбранного маршрута: этот маршрут исключится.
- Добавить новую стратегию через AbstractRouteStrategy и зарегистрировать её в
  DemoData.strategies; RoutePlanner менять не требуется.
